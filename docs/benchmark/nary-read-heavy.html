ChaosTreeMapReadBenchmark — Read-Heavy Benchmark

1. Setup

Comparing java.util.TreeMap against ChaosTree's BTreeMap and BPlusTreeMap under heavy read workloads.

java -jar ct-benchmark/target/benchmarks.jar ChaosTreeMapReadBenchmark \
    -p size=100000 -p seed=42 -wi 10 -w 500ms -i 10 -r 500ms -tu ns -rf text -rff ReadHeavy100K.txt

java -jar ct-benchmark/target/benchmarks.jar ChaosTreeMapReadBenchmark \
    -p size=10000  -p seed=42 -wi 10 -w 500ms -i 10 -r 500ms -tu ns -rf text -rff ReadHeavy10K.txt

Caveats:

  • Measurements are in strictly nanoseconds (ns/op), average time (avgt), shown as score ± error (JMH 99.9% confidence interval).
  • 10 warmup + 10 measurement iterations of 500 ms each (30 samples per cell: Cnt = 30). GC profiler (-prof gc) is not attached in this run.
  • Two sizes run: 10,000 and 100,000 entries — same seed (42) across both, ensuring parity in cache scaling boundaries.
  • preFill=true is implicitly forced for all methods here, as read benchmarks inherently require querying an already populated data structure.
  • Lower is better.
